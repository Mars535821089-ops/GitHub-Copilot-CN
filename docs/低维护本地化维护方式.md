# GitHub Copilot 桌面版低维护本地化

## 能力结论

截至 2026-10-29，GitHub Copilot 桌面应用的官方[自定义文档](https://docs.github.com/en/copilot/how-tos/github-copilot-app/customize-github-copilot-app)、[产品说明](https://docs.github.com/en/copilot/concepts/copilot-surfaces/github-copilot-app)和[帮助文档索引](https://docs.github.com/en/copilot/how-tos/github-copilot-app)未提供 UI 语言包、本地化 API 或可由产品更新兼容的界面扩展点。文档中的自定义能力面向 MCP、插件、技能和工作流，不是应用 UI 语言包。不能安全地把 VS Code 的语言包安装/选择机制照搬到 Copilot 桌面版。

因此，本仓库不能承诺自动适配新版或完整免维护。现有译文仍是针对 macOS arm64 上 Copilot 1.1.33 打包前端的本地资源补丁；官方界面无扩展接口时，任何实际应用译文的方式都依赖非官方实现细节。更新检查采用保守策略：未知版本只生成候选差异并停止，不自动改写、替换或重新签名用户正在使用的应用。

## 更新后检查

准备 Python 3、Brotli Python 依赖，以及 Node.js 和仓库锁定依赖。首次使用可在仓库根目录安装 Node 依赖：

```sh
npm ci --prefix work/runtime
python3 -m pip install -r requirements.txt
python3 scripts/check-upstream.py '/Applications/GitHub Copilot.app'
```

应用路径可作为第一个参数传入。若版本和主程序、文本资源指纹都与已审查的 1.1.33 基线一致，命令以状态码 0 报告已支持。检测到未知版本/指纹时会：

- 将应用主程序及 Info.plist 作为只读输入；临时提取的资源放在系统临时目录。
- 在新的 `outputs/upstream-review-*` 目录保存 `upstream-review.json`、精确词典生成的 `translated-assets/` 和 `candidate.diff`。
- 列出新增、移除或变化的资源指纹；不覆盖已存在的预览目录。
- 以状态码 3 结束并明确要求审查。若资源结构、压缩或源码无法识别，则报错停止，不生成可应用补丁。

`scripts/build-local.sh` 也会在保存原版副本或构建应用之前运行此检查。新版本必须先人工审查差异、验证资源结构并有意更新基线；不能仅因构建失败就把新版指纹加入清单。更新检查不是后台常驻监视器，也不会从产品更新器自动触发；应在 Copilot 完成自身更新后运行该命令，或运行构建脚本时自动检查。

## 签名、安装与回滚边界

更新检查和差异预览不写入 `.app`，不会覆盖安装目录、改动用户数据或改变代码签名。只有现有的 `build-local.sh` 会把已知原版复制到仓库的 `outputs/`，修改副本内的嵌入资源，再使用用户本机提供的 Apple Development 身份签名输出副本；该输出不是 GitHub 官方签名应用。原版输入不被修改。不要把本地签名构建覆盖到官方应用，也不要对未知版本运行二进制补丁。

脚本拒绝覆盖已有构建目录和原版备份。已安装的本地构建可通过 `scripts/restore-original.command` 恢复仓库保存的原版副本；该恢复操作会先保留当前安装副本，并要求应用正常退出。恢复不是逐文件回滚，也不删除用户数据。

对已审查指纹的旧中文版，可使用 `scripts/install-local.sh` 安装新构建：先验证代码签名、应用标识与相同签名团队，将完整旧安装移至仓库的时间戳备份，再替换安装目录并复核签名与主程序 SHA-256。任何未知安装指纹都会停止；不会把官方原版自动替换为本地签名构建。当前运行进程不会被强制退出，安装后的界面须正常退出再打开才生效。

## 自动化

仓库 CI 运行不依赖私有/本机应用资源快照的 AST 本地化、UI 运行时、菜单、资源池和更新指纹比较测试。构建脚本在本机原版应用资源已提取后，还会运行设置与真实源码表面回归测试。CI 不下载、修改或签署 GitHub Copilot 应用；上游二进制不公开作为 CI fixture，因此新版实际资源变化仍须由维护者在本机检查。

## 维护译文和验证补全

新增或纠正界面译文时，修改 `work/localization/reviewed-dictionary.json`，不要直接覆盖原始词典或机器翻译缓存。`dictionary.cjs` 将原始词典、表情词典、原生菜单词典和人工校订合并，供构建、预览及真实界面回归测试使用。人工校订中保留 `${0}` 等占位符的数量和顺序；模式枚举、回调参数、快捷键、代码和用户自定义内容不属于可翻译资源。

合并词典也会识别原始词典中已被纠正的旧译文，让旧资源快照中的中英混杂文字能在显示层得到校订。此兼容处理只用于受控界面，不扫描用户文件或对话数据，也不会绕过应用版本/签名检查。

单独验证本机资源时，可以把提取目录和输出目录显式传给生成器。二者不能重叠；下列命令只生成资源，不生成或安装 `.app`：

```sh
python3 work/localization/build-ui.py \
  --input-dir outputs/completion-audit/source \
  --output-dir outputs/completion-audit/build

COPILOT_TRANSLATED_ASSETS=outputs/completion-audit/build \
COPILOT_SOURCE_ASSETS=outputs/completion-audit/source/assets \
node --test work/localization/test-real-settings.cjs \
  work/localization/test-real-source-surfaces.cjs

node work/localization/verify-ui-structure.cjs \
  outputs/completion-audit/source/assets \
  outputs/completion-audit/build \
  outputs/completion-audit/structure-verification.json
```

`--input-dir` 必须先通过仓库提取器从本机应用生成，不是应用包路径。若资源已经包含本仓库可识别的旧汉化引导脚本，生成器保留其前面的原始首屏主题脚本，只替换汉化引导段，防止叠加两套运行时；发现重复引导段或源码解析错误会停止。该资源预览能力不代表未知二进制可以打补丁。

真实资源测试会检查设置、侧边栏状态、内置模板、输入提示和每一个表情说明，并核对表情短码、搜索标签和分类 ID 保持不变。资源快照检查不能替代对应用实际页面的人工验收，不能仅凭词典行数声称完全汉化。
